Architecture Overview

Factory Inventory Management System

A full-stack demo for inventory, order tracking, demand forecasting, and spending analytics — a Vue 3 single-page app backed by a FastAPI service reading in-memory mock data. No database, no auth: built for a workshop, not production.

System Architecture

Two independent dev servers — Vite (3000) and Uvicorn (8001) — connected over HTTP with CORS wide open. No database sits behind the API; all state lives in process memory.

Request / Data Flow

1
User adjusts a filter
FilterBar.vue writes to the shared useFilters() refs (period, warehouse, category, status) — a singleton composable, so every view reads the same state.
2
View requests data
The active view (e.g. Dashboard.vue) calls getCurrentFilters() and passes the result into an api.js method such as api.getDashboardSummary(filters).
3
Axios calls the API
Filters become query params on a GET to http://localhost:8001/api/... — the frontend never talks to the data files directly.
4
FastAPI filters in memory
apply_filters() and filter_by_month() run pure Python list comprehensions over the in-memory lists loaded once at startup from server/data/*.json.
5
Pydantic validates the response
Results are coerced into typed models (InventoryItem, Order, etc.) declared in main.py, then serialized to JSON.
6
Vue re-renders
The response lands in a ref(); computed() properties derive totals/charts from it, and the template updates reactively — no manual DOM manipulation.

Design Notes

What's real here

  • Clean separation: client never touches data files directly, only the API
  • Shared filter state via a composable keeps every view in sync
  • Typed responses via Pydantic models catch shape mismatches early
  • Backend covered by pytest + FastAPI's TestClient

Explicitly not production-ready

  • No database — all data resets when the server restarts
  • No authentication or authorization on any endpoint
  • CORS wide open (allow_origins=["*"])
  • No pagination, rate limiting, or persistence layer
